# 01. Voysy — 海で記録する（デモの核）

船上でボタンを押して喋るだけで、作業記録が台帳に入る。**インプットに徹する**。ゴールは「喋った内容が正しく文字になり、項目に正しく構造化されて保存される」こと。

## 設計原則：海では記録だけ、確認は陸で（11/2 追加）

船上の実作業は複数ロット・複数サイズを連続で扱う。1件ごとに画面を見て確認するやり方は現場と噛み合わない（高畑 11/2 実機確認後の判断）。
そこで Voysy は2つの使い方を持つ。

1. **作業セッション（主）**：「作業開始」を1回押せば、あとは喋りながら作業を続ける。合図の言葉で記録を区切り、「記録終了」で止める。区切りごとの生の文字はその場で保存し（Claude は呼ばない）、陸で一覧から整理・修正・確定する。
2. **1件だけ記録（従）**：従来の録音→確認→保存。短い記録やデモの予備。

Web アプリ（iPhone Safari）の制約で、最初の1タップは必要（ユーザー操作なしにマイクを開けない）。また画面を点けたままにする必要がある（ロック・ポケットでは止まる）。言葉だけでの開始やポケットでの常時認識はネイティブアプリの領域で、ハッカソン後の展開（README）に書く。

## 画面の流れ（1画面・3状態）

```
[待機] 大きな録音ボタン（直径 ≥ 120px）＋ 直近3件の記録一覧
  ↓ タップ
[録音中] 経過秒数、認識中のテキストがリアルタイムに流れる、停止ボタン
  ↓ 停止
[確認] 文字起こし全文（編集可） → 「整理する」→ 項目／値の表 ＋ 確認事項（赤）
       [保存] [もう一度話す]
  ↓ 保存
[待機] に戻り、一覧の先頭に今の記録が増える（トースト「保存しました」）
```

- 待機画面の一覧は推移グラフではなく、**日時・沖出し場所・作業・サイズ・入数** のテキスト行。保存が反映されたことが見えればよい。
- 全ボタンは濡れた手で押せる大きさ（高さ ≥ 56px）。文字 ≥ 18px。片手操作を想定し、録音ボタンは画面下部。

## 画面の流れ（作業セッション）

```
[待機] 「作業開始」（大） ／ 「1件だけ記録」（小） ／ 陸でチェック：未整理 N件
  ↓ 作業開始
[作業中] 経過時間、認識中の文、保存済みの区切り数。合図語のヒント。「記録終了」ボタン
        合図語（config/voice_cues.json）：区切り＝「次のロット」「次いきます」「区切り」… ／ 終了＝「記録終了」「作業終了」…
        区切り検出 → それまでの文を voice_segments に保存（未送信なら端末に残す）→ 次の区切りへ
  ↓ 記録終了（言葉 or ボタン）
[待機] 「陸でチェック：未整理 N件」が増える
  ↓ 陸でチェック
[一覧] 区切りごとに 時刻・生の文。文は直せる（結合・分割はここで文を編集して行う）。[整理する] [削除]
  ↓ 整理する
[確認] 既存の確認表（メモも編集可）→ [保存] で records に入り、区切りは確定済みに。次の未整理があれば続けて開く
```

## 機能要件

| ID | 要件 | 優先 |
|---|---|---|
| VO-01 | 録音開始／停止がボタン1つ。開始時に `webkitSpeechRecognition`（`lang=ja-JP`, `continuous=true`, `interimResults=true`）を起動し、認識テキストを画面に流す | Must |
| VO-02 | 停止後、テキストを編集可能な textarea に出す（誤認識を手で直せる） | Must |
| VO-03 | 「整理する」で `/api/voysy/extract` を呼び、Claude が `prompts/voysy_extract.md` に従って構造化 JSON を返す | Must |
| VO-04 | 構造化結果を「項目／値」の表で表示。`missing` に入った項目は赤字で「確認：ロット番号は？」の形で出す | Must |
| VO-05 | 「保存」で `/api/records` に POST。`raw_text` に文字起こし全文を保存 | Must |
| VO-06 | 送信失敗時（オフライン・5xx）は `localStorage` に未送信レコードとして残し、待機画面に「未送信 1件 [再送]」を出す | Must |
| VO-07 | 「もう一度話す」で録音状態に戻る（テキストは破棄） | Must |
| VO-08 | 待機画面に AI Oysterman からの作業予約（`reservations`）を「今日の予定」として一覧 | Should |
| VO-09 | 文字起こし中に `SpeechRecognition` がエラー／非対応なら、textarea に直接入力する導線を出す（iPhone のキーボード音声入力でも可） | Must |
| VO-10 | 「作業開始」1タップで連続認識を始め、「記録終了」の言葉またはボタンまで続ける。画面は Wake Lock で消さない | Must |
| VO-11 | 区切りの合図語（`config/voice_cues.json`）を確定文で検出し、それまでの文を `voice_segments` に生のまま保存（Claude は呼ばない）。合図語自体は保存しない | Must |
| VO-12 | 保存失敗（圏外・5xx）の区切りは端末に残し、待機画面の「未送信 N件 [再送]」で送る（VO-06 と同じ仕組み） | Must |
| VO-13 | 「陸でチェック」一覧：未整理の区切りを時刻順に出し、文を直せる。「整理する」で既存の確認表へ、「保存」で records に入れて区切りを確定。「削除」も可 | Must |
| VO-14 | 確認表の「メモ」は編集でき、`records.notes` に保存する | Must |

## 選別の複数サイズ帯とロット番号の型（11/2 追加）

- 選別は 1 回で複数のサイズ帯が生まれる（例：30g×60個入り×10カゴ、40g×50個入り×30カゴ）。抽出結果は `items[]` に帯ごとの `avg_weight_g / count_per_basket / basket_count` を持ち、確認表では帯ごとに 1 行（追加・削除可）。保存は帯ごとに 1 件の記録（`POST /api/records/bulk`）。斃死は全体の値なので先頭の帯にだけ付ける。待機画面の一覧は同じ発話の帯を 1 行にまとめて「30g×60個×10カゴ／40g×50個×30カゴ」と出す。
- 数値は用語集 `plausible_ranges` の範囲（サイズ 1〜200g、入数 1〜300、かご数 1〜500、斃死 0〜2000）の外なら聞き間違いとみなして null にし、「確認」に回す（30g が 330g になる誤認識対策。プロンプトとサーバー検証の両方）。
- **選別のとき沖出し場所（ライン・段）は未確定**なので、確認対象にしない（赤を出さない）。場所は沖出しの記録で付く。AI Oysterman の「前回の選別から」は、その場所の選別記録が無ければ、その場所にいるロットの最新の選別記録から引く。
- ロット番号は `R8-K◯` の型（`config/glossary.yaml` の `lot_format`）。「アールハチ ケー さん」「R8のK3」「K3」→ `R8-K3`（K だけなら今季の接頭辞を補う）。型に合わないものは null にして「確認：ロット番号は？」に回す。サーバー側でも正規表現で検証する。

## 構造化の仕様

入力例：「3番の上段、選別した。36グラムぐらい、1かご45個のまま、死んだの8個、かごは6つ」

出力（`/api/voysy/extract` のレスポンス）：

```json
{
  "work_type": "選別",
  "location_line": 3,
  "location_tier": "上段",
  "lot_no": null,
  "avg_weight_g": 36,
  "count_per_basket": 45,
  "mortality": 8,
  "basket_count": 6,
  "missing": ["lot_no"],
  "notes": null
}
```

- `work_type` は `config/glossary.yaml` の作業種（選別／分殖／沖出し／陸揚げ／揺らし／移動／その他）に正規化。「かご分け」と言われたら「分殖」にする。
- 数値は「ぐらい」「くらい」を無視して整数に。「死んだの」「死亡」「へいし」は `mortality`。「1かご○個」「入数○」は `count_per_basket`。
- 言っていない項目は `null` にし、`missing` に列挙する。**推測で埋めない**。
- `lot_no` は任意だが、未入力なら確認に出す（デモで「聞き返し」が見えるため）。
- 実装は Claude の tool use（JSON スキーマ強制）。モデルは `claude-haiku-5-5` で十分。応答 3 秒以内を目標。

## 代替案B（11/2 の実機検証で Web Speech API が使えない場合）

1. `MediaRecorder` で録音（iPhone は `audio/mp4`）→ Workers へアップロード → 外部 STT（Whisper API 等）→ テキスト。
2. それも間に合わなければ、**iPhone 標準キーボードの音声入力**で textarea に入れる運用にし、VO-01 は「録音ボタン＝キーボード音声入力を促す大きなボタン」に縮退。動画では喋って文字が出る様子は撮れる。

Claude API に音声を直接渡せるかは未確認。11/2 に最初に確認し、使えるならそれを第一候補にしてよい。

## 完成の定義

- 「作業開始」→ 2ロット分を続けて喋り（間に「次のロット」）→「記録終了」と言うと、未整理 2件になる。陸でチェックから2件とも整理・保存できる
- iPhone Safari（`*.pages.dev`）で、船上を想定した発話3種（上の例／分殖／斃死のみ）が正しく表に入る
- 未入力項目が「確認」に出る
- 保存後に一覧の先頭に出る
- 機内モードで保存→未送信に残る→解除して再送できる

## 縮退案（11/3 夜までに完成の定義を満たせない場合）

VO-06（再送）を落とす。VO-08 を落とす。構造化の項目を `work_type / location / avg_weight_g / mortality / basket_count` の5つに絞る。
