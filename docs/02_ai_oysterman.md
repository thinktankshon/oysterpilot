# 02. AI Oysterman — 海から学ぶ

悩みをテキストで伝えると、Voysy の記録と周防灘の水温を読み、`config/rules.yaml` の7ルールに従って「次の作業」を理由つきで提案するチャット。**ルール表が根拠**。範囲外は断定せず「先輩に聞く項目」として返し、「専門家に相談する」ボタンを出す。

## 画面

- チャット UI（吹き出し）。上部に相談対象の **沖出し場所セレクタ**（例：3番ライン・上段）。選ぶと、その場所の直近記録（前回の選別からの日数、サイズ、入数、斃死）がカードで表示される。
- 入力はテキスト（音声なし）。送信ボタンは大きく。
- AI の提案の下に **[この作業を予約する]** ボタン。押すと `reservations` に書き、「Voysy に『明日：3番ライン上段 揺らし強め』を予約しました」とシステム吹き出しを出す。
- 範囲外の回答の下に **[専門家に相談する]** ボタン（リブルの問い合わせページへのリンク。デモでは押さない）。
- Oyscan からの引き継ぎ：URL に `?from=scan&report=<id>` があれば、最初のシステム吹き出しに診断の要点（水温リスク）を出し、「この海で始めるときの注意」を聞ける状態にする（Should）。

## 機能要件

| ID | 要件 | 優先 |
|---|---|---|
| AO-01 | テキストで相談できる | Must |
| AO-02 | 選択中の沖出し場所の記録を D1 から読み、`days_since_last_sort`・`avg_weight_g`・`count_per_basket`・`basket_total_kg`（= weight × count ÷ 1000）を計算してコンテキストに渡す | Must |
| AO-03 | 周防灘の水温コンテキストを渡す：直近7日の平均・最高・最低、28℃以上の連続日数、10℃未満の連続日数、15〜25℃に入っているか（`/api/env/suonada`） | Must |
| AO-04 | 判断に足りない情報は1つだけ聞き返す（例：「下段も同じ様子？」「殻は伸びている？ツルツル？」） | Must |
| AO-05 | `config/rules.yaml` に基づき、次の作業を理由つきで提案。該当ルールの ID を内部的に返す（ログ用。画面には出さない） | Must |
| AO-06 | ルール外・満足しない旨（「分からない」「解決しない」）→「先輩に聞く項目」として整理して返し、[専門家に相談する] を表示 | Must |
| AO-07 | 「予約して」「記録に入れといて」または [予約する] ボタンで `reservations` に書き戻す（予定日・場所・作業・理由・会話ID） | Must |
| AO-08 | システムプロンプトに `config/glossary.yaml`（用語・作業規律）と `config/rules.yaml` を注入（RAG 不要） | Must |
| AO-09 | Oyscan の診断レポートを引き継いで相談できる | Should |
| AO-10 | 会話履歴はブラウザ内（state）だけで保持。D1 には予約だけ書く | Must |

## ルールの適用方法（実装メモ）

- ルール判定は **コード側で先に評価**し（`apps/api/src/rules.ts`）、「今この場所で成立している条件」のリストを作って Claude に渡す。Claude は言い回しと聞き返しを担当する。閾値の判断を LLM に任せない。
- 評価結果の例：
  ```json
  {
    "env": {"mean7": 19.8, "hot_streak": 0, "cold_streak": 0, "in_growth_band": true},
    "lot": {"days_since_last_sort": 19, "avg_weight_g": 36, "count_per_basket": 45, "basket_total_kg": 1.62},
    "fired": ["R3_growth_check"],
    "advice_targets": {"basket_kg": 1.5}
  }
  ```
- ルール同士の関係（`rules.yaml` に記述）：
  - R2（低水温）が成立中は R7 の選別目安を 30→45 日に伸ばす
  - R1（高水温）と R7 が同時なら「選別しましょう。高水温なので手早く」
  - R3（15日・見てみましょう）→ R7（30日・選別しましょう）は段階。両方は出さず、後者を優先
  - R4（入数目安）は警告ではなく、選別の話が出たときの助言として添える。通常 2.0kg、R1/R3 成立中または身質不良は 1.5kg、揺れを抑えたいとき 2.5kg
- 言い回しの禁止：「死にます」「必ず」「予測」。高水温は「斃死が増えやすい時期です」まで。

## デモの会話（この通りに動くこと）

前提：11月上旬、周防灘 15〜25℃、3番ライン上段は前回の選別から19日（10/20）、36g・45個/かご。

1. ユーザー：「3番ラインの貝、刃先がひょろっと伸びてきた。このままでいい？」
2. AI：「記録を見ると、3番ライン上段は前回の選別から19日、36gで1かご45個ですね。今は水温が15〜25℃で成長が早い時期なので、刃先が伸びやすいです。上段だけですか？ 下段も同じ様子ですか？」
3. ユーザー：「上段だけ。下段はまだ締まってる」
4. AI：「なら上段だけで大丈夫です。刃先が伸びる＝揺れが足りていない合図なので、揺れの強い場所に移すのがおすすめです。次の選別では、今の時期は1かご1.5kgを目安に薄めに（36gなら40個ほど）。下段は次の潮まで様子見で。」 ＋ [この作業を予約する]
5. ユーザー：「了解、明日やる。記録に入れといて」
6. システム：「✓ Voysy に『明日：3番ライン上段 揺れの強い場所へ移動・次回選別は1.5kg目安』を予約しました」

水温が 15〜25℃ に入っていない日に撮る場合は、2 の「成長が早い時期」を言わず、4 は揺れ・入数の提案だけにする（ルール評価がそうなるので自動で変わる）。

## 完成の定義

- 上のデモ会話が、サンプルデータに対して安定して（3回中3回）同じ趣旨で返る
- 範囲外の相談（例：「ノロウイルスは大丈夫？」）で [専門家に相談する] が出る
- 予約が D1 に入り、Voysy の待機画面（VO-08）に出る

## 縮退案

AO-09（Oyscan 引き継ぎ）を落とす。聞き返し（AO-04）を「下段も同じ？」の1パターンに固定する。
