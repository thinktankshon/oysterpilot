### プロジェクト概要（1 文＋500 字以内。合計 497 字。11/6 審査基準に合わせて書き直し）

このプロジェクトは、牡蠣養殖を新しく始める人の「その海で育つか判断できない・濡れた手では記録が残らない・相談相手がいない」という課題を、Claude を組み込んだ 3 つの道具で一人で回せる形に変える Web アプリです。

私たちは国内最大級のシングルシード養殖を営み、全国の新規参入者の立ち上げを支援してきました。その現場で足りないのは、揺れる船の上で濡れた手でも残せる記録と、記録を読んで隣で答えてくれる先輩です。記録が残らず判断の材料が貯まらず、聞ける人もおらず、最初の1年でつまずく人がいます。生産者は港で Voysy の「作業開始」を一回押し、船上では喋るだけ。陸に戻ると Claude が発話を作業の型に整理し、聞き間違いは空欄にして確認を求めます。作業の合間に AI Oysterman へ「刃先が伸びてきた、このままでいい？」と聞くと、記録と水温と10のルールをもとに先輩のように答え、分からないことは専門家へ誘導します。自治体や漁協は Oyscan で海をクリックし、斃死リスクと成長スピードを見ます。ハッカソン後は、自社の漁場と支援先の生産者が日々の記録と相談に使い続けます。

### 開発中に一番詰まった場面（草案・11/6 書き直し：非エンジニアが Claude Code で作り込む側の視点）

①何を作ろうとしていましたか？
Voysy です。船の上で喋るだけで作業記録が残る仕組みを、コードを書けない私が Claude Code との対話だけで作ろうとしていました。

②Claude にどのように指示しましたか？
「録音ボタンを押して喋ると文字になり、Claude が作業・場所・サイズ・斃死の項目に整理し、確認表で直して保存、一覧に並ぶ」という流れを、画面の順番どおりに言葉で指示しました。要件はドキュメント（docs/）に先に書き、Claude Code にはそれを読んで作らせました。

③何が起きましたか？
指示どおりに動くものが、その日のうちにできました。ところが iPhone を持って実際に船へ出ると、濡れた手と揺れる足元では画面に触れず、1 件ごとに確認表を直して保存する流れそのものが成立しませんでした。AI Oysterman も同じで、「場所を選んで相談する」画面は作業の合間には使えず、Oyscan も西日本の海域だけでは出力のパターンが乏しくて、デモになりませんでした。

④期待していた結果と何が違いましたか？
Claude Code は言われたとおりに正確に作ります。違っていたのは私の指示でした。作りたいものを言葉で伝えたつもりでも、現場の体の動き（手が濡れている、画面を見られない、場所はあとで決まる）までは伝えられておらず、動くものを実機で触って初めて分かりました。コードを読めない私には、できたものが正しいかを画面でしか判断できない、という点も想定より重くのしかかりました。

⑤どのように対処しましたか？
作り方そのものを変えました。コードを変える前に Claude Code から「目的・影響範囲・実装方法・リスク」の 4 点を出させ、私が GO を出してから作る。できたら必ず iPhone の実機で、できれば現場で触り、その場の指摘をもとに作り直す。決まったことは決定ログに 1 行ずつ残し、現場の用語は用語集に置いて「分からない語は推測せず私に聞く」とルール化する。この型で Voysy は「海では喋るだけ、確認は陸で」に、AI Oysterman は「作業中に話しかけるチャット」に、Oyscan は全国 80 海域に作り直しました。コードを読めない分は、Claude Code に画面以外の確かめ方を作らせました。現場の用語と言い回しはスキルに、実名・秘密情報・禁止表現の検査はコミット直前に走るフックに、ルール表の矛盾チェックは読み取り専用のサブエージェントに、会話の品質は 16 ケースの評価テスト（pnpm eval）に置き、私が毎回言わなくても守られる形にしました。

### Claude を使った感想と改善してほしい点（草案）

①日本語や日本の業務で使う立場から気づいた欠点と利点（具体例）
利点：現場の言葉を守れることです。「分殖（かご分けではない）」「刃先」「漁場・レーン・間」のような、辞書にない現場語と言い回しのルールを用語集（config/glossary.yaml）とスキルにまとめて渡すと、Voysy の整理も AI Oysterman の返答も docs も、その語で揃いました。生産者の喋り言葉（「R8のK3、陸揚げ。D漁場 5レーン 5間目から12間目」）を項目に読み分ける精度も、日本語の数量表現（「10かご」「15リットル」「60個入り」）を含めて実用でした。
欠点：言い切りが混じることです。養殖の現場では「死にます」「必ず」「安全です」と言ってはいけないのに、プロンプトで禁じても一定の割合で混じりました。最終的にサーバー側に禁止語の検査を置き、さらに「数字の判断は LLM に任せず、ルール表をコードで判定して Claude は言い回しだけ」という設計に寄せることで解決しました。もう一つ、否定形（「必ず死ぬわけではありません」）まで検査が弾いてしまい、正しい返答が固定文に置き換わった失敗もあり、検査の設計に手間がかかりました。
Claude Code の運用では、目的ごとに置き場所を分けるのが効きました。用語と言い回しはスキル、コミット前の検査は PreToolUse のフック、ルール表の確認は読み取り専用のサブエージェント、作業のルール（4 点セット→GO、コミット前の diff 要約、push は承認後）は CLAUDE.md。コードを書けない私でも、この置き場所を決めることで開発の手綱を握れました。

②他の AI ツールと比べて劣る点と優れる点
比較なし

③一つだけ直せるとしたら何か、その改善で何が作れるようになるか
Claude API が音声をそのまま受け取れるようにしてほしいです。今回は Claude が音声入力に対応していなかったため、海上の音声→文字はブラウザの Web Speech API に任せ、Claude は文字になった後の整理しか担えませんでした。聞き間違い（30g が 330g）はこの段階で起きます。音声を直接渡せれば、現場語の辞書と作業の型をプロンプトで持たせたまま文字起こしと整理を一度に行え、「港で 1 回押したらあとは喋るだけ」から、Siri や電話番号で始めて喋るだけで記録が残る形まで、一気に近づきます。

**English (100 words)**
OysterPilot removes three walls for people starting single-seed oyster farming: not knowing whether a sea will grow oysters, not being able to keep records with wet hands on a boat, and having no one to ask. Oyscan maps 80 coastal areas of Japan and rates mortality risk and growth speed from JMA water temperature and rainfall. Voysy lets farmers keep talking while they work; Claude turns the speech into structured records and asks about missing fields. AI Oysterman reads records and temperature, evaluates ten field rules in code, draws on Re:Blue's practice and cited knowledge, and answers as a companion.

**今後の展開（文字数に余裕があれば添える・11/6 追加）**
Voysyの起動は、今回はWebの制約で港での1タップが要ります。本実装では、Siriに「Voysy、作業開始」と言うだけで音声の取り込みが始まるネイティブアプリと、IP電話の番号に電話をかけると記録が残り、そのままAI Oystermanと会話もできる電話番号方式を想定しています。画面にさわらずに始められれば、海の上での記録はさらに自然になります。

*English:* Starting Voysy still takes one tap at the dock because of browser limits. In production we envision a native app that Siri launches by voice, and a phone‑number model: call an IP phone number, speak, and the records are kept — the same call can continue as a conversation with AI Oysterman.
